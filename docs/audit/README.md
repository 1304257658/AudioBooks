# 产品审计分支规则

当前分支：`codex/audit`

该分支是 AudioBooks 产品审计的长期基线，用于保存审计报告、证据截图、问题编号、复审结论和验收状态。

## 分支职责

该分支允许修改：

- `docs/audit/` 下的审计报告、截图和辅助证据
- `docs/governance/` 下与审计流程直接相关的规则
- 与审计流程直接相关的说明文件

该分支不修改：

- Android 产品代码
- 构建配置和运行时依赖
- 为修复审计问题而产生的 UI、交互或业务逻辑实现

产品修复必须在其它功能分支完成。修复分支从当前产品开发基线创建，在分支名、提交或 PR 中引用对应审计编号，例如 `AUD-P0-001`。修复完成后，再在 `codex/audit` 分支进行复审并更新问题状态。

## 审计前同步

每次开始审计前，必须先保证工作区干净，然后依次：

1. 获取远端最新状态：`git fetch origin`。
2. 更新审计分支：`git pull --ff-only origin codex/audit`。
3. 将最新产品基线合入审计分支：`git merge --no-edit origin/main`。
4. 在新报告中记录实际审计的 `origin/main` 提交哈希。

若同步产生冲突，先停止审计并解决冲突；不得使用旧代码继续审计，也不得用破坏性命令丢弃已有审计内容。

## 审计记录要求

每次产品审计必须记录：

1. 被审计的版本、提交或 APK。
2. 测试设备、系统版本和数据状态。
3. 实际走查的用户目标与完整步骤。
4. 当前审计运行中获取并检查过的截图。
5. 按 `P0/P1/P2` 排序的问题及稳定编号。
6. 每个问题对应的明确修改内容和验收标准。
7. 无法从截图或当前环境确认的证据边界。

## 问题状态

审计问题使用以下状态：

- `待修复`：问题已确认，尚未提供修复版本。
- `待复审`：其它分支已提供修复，需要在审计分支重新走查。
- `已通过`：修复版本已按原流程复测并满足验收标准。
- `未通过`：已复测，但问题仍存在或产生新的阻断。
- `不再适用`：产品方向或功能范围发生变化，原问题不再成立；必须记录原因。

只有在当前版本上重新执行相关流程并取得新的证据后，问题才能改为 `已通过`。代码已提交、测试已通过或开发者说明已修复，都不能替代产品复审。

## 文件约定

- 审计报告：`docs/audit/reports/`
- 截图与 UI 证据：`docs/audit/evidence/<审计日期>/`
- 截图按流程顺序编号，并使用可读名称，例如 `01-empty-library.png`
- 后续复审增加带版本或日期的报告，不覆盖旧证据
- 报告中的问题编号一旦发布不得复用
